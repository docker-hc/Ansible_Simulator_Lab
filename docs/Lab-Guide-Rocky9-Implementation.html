01 Lab architecture & network

The lab runs entirely inside VirtualBox on a Windows host. A single management node carries Ansible, SAM4H, and CCI/HORCM; four integsim virtual machines each emulate one VSP One B26 array; two lightweight RHEL nodes stand in as storage hosts. Two networks separate concerns: a bridged network (192.168.2.0/24) for real-world reachability and SAM4H/REST traffic, and an internal network (192.168.56.0/24) for Ansible control.

Why Rocky 9, not RHEL 10
The host CPU is an Intel i7-8550U (Kaby Lake), which supports only the x86-64-v2 microarchitecture level. RHEL 10 requires x86-64-v3 and will fail to boot on pre-2019 Intel silicon. Rocky Linux 9.7 is the correct base for this hardware.

02 Host prerequisites (Rocky 9)

Every VM starts from a minimal Rocky Linux 9.7 install. The management node needs the fullest package set; the simulator VMs need a base plus build tooling for VirtualBox Guest Additions and integsim's nginx dependency.

Base packages (all nodes)

bash — all nodesroot
# EPEL for shellcheck and assorted tooling
dnf install -y epel-release
dnf install -y git curl wget tar vim tree jq \
    gcc make kernel-devel-$(uname -r) elfutils-libelf-devel \
    python3.11 python3.11-pip shellcheck
Use python3.11 for the automation stack
System Python on Rocky 9 is 3.9 and caps ansible-core at 2.15.13. The lab standardises on python3.11 -m pip for ansible-core 2.16.18, ansible-lint, yamllint, and openpyxl. Mixing the two interpreters is the most common cause of "module not found" at runtime.

Kernel quiet-boot (cosmetic)

integsim and HORCM are chatty at the console. Trim kernel verbosity so the serial console stays readable across reboots:

bash — all nodesroot
grubby --update-kernel=ALL --args="quiet loglevel=3"
grub2-mkconfig -o /boot/grub2/grub.cfg

03 Management node build

The management node is the only host that operators log into. It runs the Ansible control process, the SAM4H container stack, and all HORCM instances.

Ansible control stack

bash — mgmt noderoot
python3.11 -m pip install ansible-core==2.16.18 ansible-lint yamllint openpyxl
ansible-galaxy collection install ansible.posix brocade.fos \
    hitachivantara.vspone_block:==4.8.1

Vault & SSH key material

bash — mgmt noderoot
# Vault password file (referenced from ansible.cfg)
echo 'VaultMaster2026!' > /root/.vault_pass
chmod 600 /root/.vault_pass

# Dedicated lab key + a separate GitHub key
ssh-keygen -t ed25519 -f /root/.ssh/ansible -N ''
ssh-keygen -t ed25519 -f /root/.ssh/github  -N ''
GitHub is the real backup
VirtualBox snapshots share a base disk and can corrupt together. The authoritative backup is the Git repository git@github.com:docker-hc/Ansible_Simulator_Lab.git. A full rebuild from a clean Rocky 9 image to a working lab takes under an hour when the repo is intact. Commit after every milestone.

04 SAM4H deployment

Storage Advisor for Hitachi (SAM4H v2.4.3b) ships as a container stack run under Podman. It provides the registration UI and drives the CCI reload that populates each array's cache and microcode view.

Podman prerequisites

bash — mgmt noderoot
dnf install -y podman podman-docker podman-compose
ln -s /usr/bin/podman-compose /usr/bin/docker-compose
systemctl enable --now podman.socket

RESTART ON UI 500

A first-boot race in aardvark-dns can leave the UI returning HTTP 500. Restarting the service after the containers settle clears it:

bash — mgmt noderoot
systemctl restart sam4h.service
sleep 30
podman ps --format "{{.Names}} {{.Status}}"

The UI is reachable at https://192.168.2.91:8080. Default first login is root / Root1234; the lab password is Sam4h2026!.

05 CCI & HORCM setup

CCI (Command Control Interface) is installed from the RMHORC cpio bundle. All HORCM instances run on the management node only — the simulator VMs already occupy port 31001 with integsim's IPCMD listener, so HORCM cannot also bind there.

HORCM_CMD uses the IPCMD form

This is the single most important detail of the HORCM configuration. integsim arrays are reached through a special command-device URL, not a real device path and not a plain IP:

/etc/horcm1001.conf — mgmt nodeexcerpt
HORCM_MON
192.168.2.91    34001    1000    3000

HORCM_CMD
\\.\IPCMD-192.168.2.90-31001
HORCM_MON port allocation
Every instance needs a unique monitor port. integsim's listener owns 31001 on each array, so HORCM_MON ports are placed at 34001–34006 to avoid any collision. The command path stays at the IPCMD …-31001 form because that is the array side, reached over the network.

Instance ↔ array mapping

SAM4H auto-assigns HORCM instance numbers and re-increments them whenever an array is deleted and re-added. The current mapping reflects a mid-build re-registration of two arrays:

Edit, don't delete-and-re-add
Because SAM4H re-increments on re-add (840006 moved 1002→1005, 845665 moved 1003→1006), avoid deleting an array to fix it. Edit the existing record instead. If you must re-add, expect a new instance number and update group_vars/vault.yml, the HORCM config files, and lab-startup.sh to match.

Verify each instance

bash — mgmt noderoot
for i in 1001 1004 1005 1006; do
  echo -n "HORCM $i: "
  raidqry -l -IH${i} | grep -vE '^No|^$|^Group' | head -1
done

Each line should report the matching serial, microcode A3-00-00/00, and cache 285184 MB.

06 integsim array build

integsim v10.2 emulates a full VSP One B26 REST/CCI surface. Each simulator VM runs one instance bound to a unique serial number. The build has three fiddly dependencies that are easy to miss.

1

NGINX NEEDS LIBXCRYPT-COMPAT

integsim's bundled nginx links against libcrypt.so.1, which Rocky 9 no longer ships by default.

bash — sim VMroot
dnf install -y libxcrypt-compat
2

CONFIG GENERATOR PATCH

The array personality is defined in customed_config.json under the generator resource directory. The setup script must be pointed at it before first run.

bash — sim VMroot
# config lives here:
/root/integsim/src/dkc-simulator/resource/generator/customed_config.json

# point the generator at it (one-time sed on the setup script)
sed -i 's/JSONGEN_FILENAME=.*/JSONGEN_FILENAME=customed_config.json/' \
    /root/integsim/src/dkc-simulator/setup-dkc-simulator.sh
3

SET SERIAL, THEN RUN SETUP

bash — sim VMroot
sed -i 's/^DKCSIM_SERIALNUM=.*/DKCSIM_SERIALNUM=810294/' \
    /root/integsim/settings.txt
EXT_IP=192.168.2.90 /root/integsim/setup.sh
/root/integsim/start.sh

SSH from the mgmt node — LEGACY crypto

A clean Rocky 9 clone uses the DEFAULT crypto policy, which the mgmt node's newer OpenSSL rejects with kex_exchange_identification: Connection reset by peer. Set LEGACY on each simulator:

bash — sim VMroot
update-crypto-policies --set LEGACY
systemctl restart sshd

Verify the REST surface

bash — mgmt noderoot
curl -sk -u maintenance:raid-maintenance \
  https://192.168.2.90/ConfigurationManager/v1/objects/storages \
  | jq -r '.data[0].serialNumber'

The maintenance / raid-maintenance credential is OS-authenticated (extAuthFlg=1) — the OS user maintenance (uid 1000) must exist with that password. Reset with echo 'maintenance:raid-maintenance' | chpasswd if CCI auth fails.

07 Cloning additional arrays

Arrays two through four are full clones of the first working simulator. The order of operations matters — the cloned image inherits the source's IP aliases and SSH host key, both of which must be cleared.

Remove inherited IP aliases first
The 810294 image carried stale aliases (.93/.94/.95/.96) that caused SSH from mgmt to land on the wrong VM. Strip them before or immediately after cloning.
bash — freshly cloned sim VMroot
# 1 — clear inherited address aliases
nmcli con mod enp0s3 -ipv4.addresses 192.168.2.93/24
nmcli con mod enp0s3 -ipv4.addresses 192.168.2.94/24

# 2 — set this clone's identity
nmcli con mod enp0s3 ipv4.addresses 192.168.2.93/24
hostnamectl set-hostname rocky9-sim-840006
sed -i 's/^DKCSIM_SERIALNUM=.*/DKCSIM_SERIALNUM=840006/' /root/integsim/settings.txt

# 3 — disable IPv6 dup-address (clones share a MAC seed)
nmcli con mod enp0s8 ipv6.method disabled

# 4 — re-run integsim setup for the new serial/IP
EXT_IP=192.168.2.93 /root/integsim/setup.sh
/root/integsim/start.sh

On the mgmt node, clear the old host key for any reused IP before reconnecting:

bash — mgmt noderoot
ssh-keygen -R 192.168.2.92

08 Registering arrays in SAM4H

With all four REST surfaces answering, register each array in the SAM4H UI. SAM4H then runs a detailed CCI reload that populates cache size and microcode in the array list.

840006192.168.2.93maintenanceraid-maintenance
845665192.168.2.92maintenanceraid-maintenance
845666192.168.2.94maintenanceraid-maintenance
0 Bytes cache after registration?
If an array lists 0 Bytes cache and a blank microcode while its CCI column is empty, the OS maintenance password is wrong on that simulator. Reset it (echo 'maintenance:raid-maintenance' | chpasswd), restart integsim, then trigger a detailed reload. A reload that finishes in a few seconds without running the raidcom sequence means HORCM for that instance was not reachable.

09 Ansible project structure

The project lives at /etc/ansible/Ansible_Simulator_Lab. Always cd there before running anything — the inventory and vault paths in ansible.cfg are relative, and running from elsewhere yields "No inventory parsed".

Inventory groups

Hosts are grouped controller, simulator, nodes, and mgmt, with a lab:children roll-up. Per-host facts (internal IP, bridged IP, array serial, HORCM instance) live in host_vars/; shared data lives in group_vars/.

Regenerate the structure view

The show-structure.sh grapher renders the live tree, the inventory graph, the script and collection inventory, and the running HORCM map in one pass:

bash — project rootroot
bash scripts/show-structure.sh | tee /mnt/vm_share/lab-structure.txt

Lint before every commit

lint-check.sh runs seven gates: yamllint, ansible-lint, syntax-check, inventory graph, vault-is-encrypted, vault-pass-not-tracked, and shellcheck on all scripts.

bash — project rootroot
bash scripts/lint-check.sh
# Results: 7 passed, 0 failed → safe to commit and push

10 vspone_block collection

The hitachivantara.vspone_block 4.8.1 collection provides 102 VSP modules. The vendor ships example playbooks under vsp_direct/, copied into the project for reference and reuse.

Vault variables for direct connection

The example playbooks read connection details from a relative path. Create the vars file once:

playbooks/ansible_vault_vars/ansible_vault_storage_var.ymlexcerpt
storage_address: 192.168.2.90
vault_storage_username: maintenance
vault_storage_secret: raid-maintenance

Accept the usage consent once

bash — project rootroot
ansible-playbook playbooks/vsp_direct/accept_user_consent.yml
Vendor playbooks & ansible-lint
The 60+ vendor example playbooks carry ~360 upstream name[unique] violations that are not the lab's to fix. The project's .ansible-lint excludes playbooks/vsp_direct/ and playbooks/ansible_vault_vars/ so the lint gate stays at 7/7 on lab-authored content.
.ansible-lint — project root
profile: moderate
exclude_paths:
  - playbooks/vsp_direct/
  - playbooks/ansible_vault_vars/
warn_list:
  - yaml[line-length]

11 Facts-export toolchain

The export pipeline gathers six fact types plus HBA WWN logins from every array, then builds a formatted Excel workbook and matching CSVs, with a run-over-run diff. One command runs the whole thing:

bash — project rootroot
bash scripts/run-facts-export.sh

What it produces

  • Summary tab — one row per array (model, microcode, capacity, efficiency, object counts) with a SUM total row.
  • Changes tab — diff versus the previous run: added (green), changed (amber), removed (red).
  • Per-array tabs — all six fact types stacked, plus an HBA-WWN section.
  • All-<fact type> tabs — arrays stacked with a serial column; added rows and changed cells highlighted.
  • All-HBA-WWNs tab — logins (from raidcom) and registered WWNs (from the module), keyed for migration planning. Empty host groups are flagged.
  • CSV mirror in exports/csv/, and an auto-copy of everything to /mnt/vm_share (D:\vsp_facts_export).
Migration data: WWN logins & empty host groups
On the simulators numberOfHbasPerHostGroup is 0, so the first run correctly shows zero HBA WWNs and every host group flagged empty — the clean migration baseline. As initiators are registered or hosts log in, they populate the All-HBA-WWNs tab and the empty flags clear.

Outputs are regenerable, so exports/ is git-ignored. openpyxl must be installed under python3.11 for the workbook step.

12 Startup & persistence

A boot-time script brings the lab up in the correct order: network, then SAM4H, then the simulator REST surfaces, then HORCM. The simulator VMs autostart integsim from their own crontab; the mgmt node starts HORCM only after all four REST APIs answer.

crontab — mgmt noderoot
@reboot sleep 30 && /usr/local/bin/lab-startup.sh

The script restarts SAM4H if fewer than four containers are up, waits for the four simulator REST endpoints to return HTTP 200/302, then starts HORCM instances 1001/1004/1005/1006 and verifies each with raidqry. It logs to /var/log/lab-startup.log. Boot to fully-operational is roughly 90 seconds. The full script and its failure modes are documented in the Troubleshooting Guide.

After any change
Run scripts/lint-check.sh → commit → push, then snapshot the affected VMs. The mgmt node snapshot name in current use is Rocky9-lab-vspb26-facts-export-may2026. Remember: snapshots can fail together — GitHub is the backup that matters.

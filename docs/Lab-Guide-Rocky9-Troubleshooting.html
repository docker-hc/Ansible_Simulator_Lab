01 The operational scripts

Four scripts run the lab day to day. They live in scripts/ under the project root, and every one of them is checked by lint-check.sh (shellcheck for shell, AST parse for Python) before commit. This section reproduces each in full and explains the parts that matter when something breaks. All scripts assume you have cd'd to /etc/ansible/Ansible_Simulator_Lab first, or they resolve the project root themselves via cd "$(dirname "$0")/..".

Interpreter discipline
Shell scripts call python3.11 explicitly, never bare python3. System Python on Rocky 9 is 3.9 and lacks the lab's openpyxl / ansible-core install. A "ModuleNotFoundError: openpyxl" almost always means a script was edited to call python3 instead of python3.11.

02 lint-check.sh — the 7 gates

The pre-commit gate. Seven independent checks, each printed pass/fail, with a non-zero exit if any fail. The vault checks are safety rails: they confirm the vault is actually encrypted and that the vault password file is never tracked by Git.

scripts/lint-check.shbash
#!/bin/bash
# Lab lint & verification — 7 gates, non-zero exit on any failure.
cd "$(dirname "$0")/.."
pass=0; fail=0
ok(){ echo "✓ $1 passed"; pass=$((pass+1)); }
no(){ echo "✗ $1 FAILED";  fail=$((fail+1)); }

# 1 — yamllint
yamllint . && ok "yamllint" || no "yamllint"
# 2 — ansible-lint (honours .ansible-lint excludes)
ansible-lint && ok "ansible-lint" || no "ansible-lint"
# 3 — syntax check every playbook
ansible-playbook --syntax-check playbooks/*.yml && ok "syntax" || no "syntax"
# 4 — inventory parses into a graph
ansible-inventory --graph >/dev/null && ok "inventory" || no "inventory"
# 5 — vault is actually encrypted
head -1 group_vars/vault.yml | grep -q '\$ANSIBLE_VAULT' \
  && ok "vault encrypted" || no "vault encrypted"
# 6 — vault password file not tracked by git
git ls-files --error-unmatch .vault_pass 2>/dev/null \
  && no "vault_pass tracked" || ok "vault_pass not tracked"
# 7 — shellcheck every script
shellcheck scripts/*.sh && ok "shellcheck" || no "shellcheck"

echo "Results: $pass passed, $fail failed"
[ "$fail" -eq 0 ] || exit 1
Gate 2 fails with ~360 violations?
If ansible-lint reports hundreds of name[unique] errors, the .ansible-lint exclude file is missing or not at the project root. The vendor vsp_direct/ playbooks carry those upstream violations. See issue A-2 for the exact exclude file.

03 lab-startup.sh — boot order

Run at boot from the mgmt node crontab (@reboot sleep 30 && /usr/local/bin/lab-startup.sh). The ordering is deliberate: SAM4H first, then wait for every simulator's REST surface, then start HORCM. HORCM started before integsim is ready will connect to nothing.

/usr/local/bin/lab-startup.shbash
#!/bin/bash
# Arrays: 810294→1001, 840006→1005, 845665→1006, 845666→1004
LOG=/var/log/lab-startup.log
echo "$(date) — Lab startup initiated" | tee -a $LOG

# 1 — let the network settle
sleep 20

# 2 — SAM4H: restart if fewer than 4 containers up
RUNNING=$(podman ps --format "{{.Names}}" | grep -c config-)
if [ "$RUNNING" -lt 4 ]; then
  systemctl restart sam4h.service
  for a in $(seq 1 18); do
    sleep 10
    [ $(podman ps --format "{{.Names}}" | grep -c config-) -eq 4 ] && break
  done
fi

# 3 — wait for each simulator REST API (HTTP 200/302)
for ip in 192.168.2.90 192.168.2.92 192.168.2.93 192.168.2.94; do
  for a in $(seq 1 30); do
    code=$(curl -sk -o /dev/null -w "%{http_code}" https://$ip)
    [ "$code" = "200" ] || [ "$code" = "302" ] && break
    sleep 2
  done
  echo "$ip → HTTP $code" | tee -a $LOG
done

# 4 — start HORCM and verify
for i in 1001 1004 1005 1006; do
  /HORCM/usr/bin/horcmshutdown.sh $i &>/dev/null
  /HORCM/usr/bin/horcmstart.sh $i
done
sleep 5
for i in 1001 1004 1005 1006; do
  raidqry -l -IH${i} | grep -vE '^No|^$|^Group' | head -1 | tee -a $LOG
done
echo "$(date) — Lab startup complete" | tee -a $LOG

The simulator VMs autostart integsim from their own crontab (@reboot /root/integsim/start.sh), so by the time the mgmt node reaches step 3 they are usually mid-boot. The 30-attempt / 2-second loop tolerates a slow simulator without hanging the whole sequence.

04 show-structure.sh — grapher

A read-only diagnostic. It prints the project tree, the parsed inventory graph, the playbook/role/script inventory, the installed collections, and — crucially when debugging — the live HORCM-to-array map. Pipe it to the share for an offline snapshot.

scripts/show-structure.sh — key sectionsbash
cd "$(dirname "$0")/.."

# directory tree (falls back to find if 'tree' absent)
tree -L 3 -F --dirsfirst -I 'exports|.git|__pycache__'

# parsed inventory — groups, children, hosts
ansible-inventory --graph

# installed collections of interest
ansible-galaxy collection list \
  | grep -E 'hitachivantara|ansible.posix|brocade'

# LIVE array map — the money shot when CCI misbehaves
for i in 1001 1004 1005 1006; do
  line=$(raidqry -l -IH${i} 2>/dev/null | grep -vE '^No|^$|^Group' | head -1)
  [ -n "$line" ] && echo "  HORCM $i:$line" \
                 || echo "  HORCM $i: (not running)"
done
First diagnostic for "array shows wrong data"
Run this script. If the HORCM map shows an instance bound to the wrong serial, the array's HORCM config file points at the wrong IP, or SAM4H re-assigned the instance number out from under you (issue H-3).

05 Facts-export pipeline

Five stages, orchestrated by run-facts-export.sh: gather → workbook → CSV → archive → copy. The gather stage runs the Ansible playbook (six module fact types) and the raidcom WWN collector; the workbook stage diffs against the previous run.

scripts/run-facts-export.shbash
cd "$(dirname "$0")/.."
SHARE_DIR=/mnt/vm_share/vsp_facts_export
STAMP=$(date +%Y-%m-%d_%H%M%S)
PREV_ARG=""
[ "${1:-}" = "--baseline" ] && [ -n "${2:-}" ] && PREV_ARG="--prev $2"

# 1 — gather (6 module facts + raidcom HBA WWN logins)
ansible-playbook playbooks/08-export-facts.yml
# 2 — workbook with diff vs previous run
python3.11 scripts/facts_to_xlsx.py --raw exports/raw $PREV_ARG
# 3 — CSV mirror
python3.11 scripts/facts_to_csv.py --raw exports/raw --out exports/csv
# 4 — archive this run; keep last 20
mkdir -p "exports/history/$STAMP"
cp -f exports/raw/*.json "exports/history/$STAMP/"
ls -1dt exports/history/*/ | tail -n +21 | xargs -r rm -rf
# 5 — copy to the Windows share (guarded)
if [ -d /mnt/vm_share ]; then
  mkdir -p "$SHARE_DIR/csv"
  cp -f exports/*.xlsx "$SHARE_DIR/"
  cp -f exports/csv/*.csv "$SHARE_DIR/csv/"
fi

The HBA-WWN collector

WWN logins are not exposed cleanly by the module set on the simulators, so they are collected directly with raidcom — proven to work over the IPCMD HORCM instances. The collector walks ports → host groups → HBA WWNs per array and writes JSON in the same shape the modules produce, so the workbook builder treats both identically.

scripts/gather_hba_wwn.py — core looppython
def gather_array(serial, inst, user, pw):
    ih = f"-IH{inst}"; login = ["-login", user, pw]
    records = []
    for port in parse_ports(run(["raidcom","get","port",ih]+login)):
        for gid, gname in parse_host_grp(
                run(["raidcom","get","host_grp","-port",port,ih]+login)):
            for wwn, nick in parse_hba_wwn(
                    run(["raidcom","get","hba_wwn",
                         "-port",f"{port}-{gid}",ih]+login)):
                records.append({"port_id":port,"host_group_number":gid,
                    "host_group_name":gname,"hba_wwn":wwn,
                    "nickname":nick,"source":"login"})
    return records

How the diff is keyed

The workbook builder classifies each object as added / removed / changed by matching a natural identity field between runs. If a fact type appears entirely as "added" then "removed" instead of "changed", the wrong key is being used — adjust KEY_FIELDS in facts_to_xlsx.py.

Fact typeIdentity key
Storage systemserial_number
Parity groupsparity_group_id
Portsport_id
Poolspool_id / id / pool_name
LDEVsldev_id / id
Host groupsport_id + host_group_number
Empty host group flag
Each host group row gets an hba_count (distinct WWNs, counting a login and its registered twin once) and an empty flag. Empty groups are highlighted amber on the host-group tabs — the migration signal for "placeholder present, no initiators".

06 Host & OS issues

OS-1RHEL 10 will not boot on the host
kernel panic / immediate halt on a pre-2019 Intel CPU
Cause & fix

RHEL 10 requires the x86-64-v3 microarchitecture level. The host i7-8550U (Kaby Lake) is x86-64-v2 only. Use Rocky Linux 9.7 for every VM. This is non-negotiable on this hardware.

OS-2Console flooded with kernel messages
continuous dmesg/IPv6 output makes the console unusable
Fix
all nodesroot
grubby --update-kernel=ALL --args="quiet loglevel=3"
grub2-mkconfig -o /boot/grub2/grub.cfg

On the simulators, IPv6 duplicate-address warnings come from the shared clone MAC seed. Disable IPv6 on the internal NIC: nmcli con mod enp0s8 ipv6.method disabled.

OS-3ansible-core install caps at 2.15
pip installs ansible-core 2.15.13 instead of 2.16.x
Cause & fix

System Python 3.9 caps ansible-core at 2.15.13. Install the stack under 3.11: python3.11 -m pip install ansible-core==2.16.18 ansible-lint yamllint openpyxl. Confirm with ansible --version showing the 3.11 interpreter path.

07 Network & SSH issues

NET-1SSH to a clone resets the connection
kex_exchange_identification: Connection reset by peer
Cause & fix

A clean Rocky 9 clone uses the DEFAULT crypto policy, which the mgmt node's newer OpenSSL rejects. Diagnostic: ssh -o KexAlgorithms=ecdh-sha2-nistp256 … succeeds where plain ssh fails. On the simulator:

sim VMroot
update-crypto-policies --set LEGACY
systemctl restart sshd
NET-2SSH lands on the wrong simulator
connecting to 192.168.2.93 reaches the 810294 array
Cause & fix

The clone inherited the source VM's IP aliases (810294 carried .93/.94/.95/.96). Strip them, then set the clone's own address:

sim VMroot
nmcli con mod enp0s3 -ipv4.addresses 192.168.2.93/24
nmcli con mod enp0s3 ipv4.addresses 192.168.2.93/24
NET-3Host key mismatch on a reused IP
WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED
Fix

A reused address (e.g. 192.168.2.92 from a retired template) carries an old host key. Clear it on the mgmt node: ssh-keygen -R 192.168.2.92.

08 integsim issues

SIM-1nginx fails — libcrypt.so.1 missing
error while loading shared libraries: libcrypt.so.1
Fix

integsim's bundled nginx links the old libcrypt. Install the compat shim: dnf install -y libxcrypt-compat, then re-run start.sh.

SIM-2Generated array has the wrong personality
setup produces a default config, not the VSP One B26 profile
Cause & fix

The generator wasn't pointed at customed_config.json. Patch the setup script before first run:

sim VMroot
sed -i 's/JSONGEN_FILENAME=.*/JSONGEN_FILENAME=customed_config.json/' \
    /root/integsim/src/dkc-simulator/setup-dkc-simulator.sh

The config file path is /root/integsim/src/dkc-simulator/resource/generator/customed_config.json. Full detail in Document 3.

SIM-3REST API not answering after boot
curl to https://<ip> times out for ~30–60s after VM start
Expected behaviour

integsim takes 30–60 seconds to bring up its REST surface after boot. The startup script's HTTP 200/302 wait loop accounts for this. If it never answers, check start.sh ran (crontab @reboot) and that libxcrypt-compat is installed (SIM-1).

09 HORCM & CCI issues

H-1HORCM_CMD syntax — the IPCMD form
raidqry/raidcom cannot reach the array; EX_ENORMP or no response
Cause & fix

integsim arrays require the special command-device URL, not a real device path and not a plain IP:

/etc/horcm1001.conf
HORCM_CMD
\\.\IPCMD-192.168.2.90-31001

The 31001 is integsim's IPCMD listener port on the array side — always 31001 regardless of the instance's MON port.

H-2HORCM won't run on a simulator VM
port already in use when starting HORCM on a sim
Design constraint

HORCM runs on the mgmt node only. The simulator VMs already bind 31001 for integsim's IPCMD listener, so HORCM cannot also use it there. All instances live on mgmt with MON ports 34001–34006 to avoid collision.

H-3SAM4H re-assigned the HORCM instance number
an array that was instance 1002 is now 1005 after a re-add
Cause & fix

SAM4H auto-assigns instance numbers and re-increments on every delete/re-add. During this build, 840006 moved 1002→1005 and 845665 moved 1003→1006 when re-added to fix a 0-Bytes cache. The fix is to follow the change through three places:

  • Create the new HORCM config (/etc/horcm1005.conf, 1006) with the right MON port and IPCMD line; remove the stale 1002/1003 files.
  • Update group_vars/vault.yml horcm_instance for those serials.
  • Update the instance list in lab-startup.sh.

Prevention: edit the existing array record in SAM4H rather than delete-and-re-add.

H-4raidcom auth fails — OS user
login rejected for maintenance / raid-maintenance
Cause & fix

The credential is OS-authenticated (extAuthFlg=1). The OS user maintenance (uid 1000) must exist on the simulator with that exact password:

sim VMroot
echo 'maintenance:raid-maintenance' | chpasswd

10 SAM4H issues

SAM-1Array shows 0 Bytes cache, blank microcode
CCI column empty; detailed reload finishes in seconds with no raidcom run
Diagnosis & fix

Observed on 840006 and 845665. A reload that completes in a few seconds never ran the raidcom sequence — SAM4H couldn't authenticate CCI for that array. Root cause was the OS maintenance password (H-4). Sequence that resolved it:

  1. Reset the OS password on the simulator (H-4) and restart integsim.
  2. Confirm the REST surface answers and HORCM for that instance reports the serial via raidqry.
  3. Re-add the array (note: new instance number — H-3) and trigger a detailed reload.

A healthy reload runs the full raidcom sequence (system, port, pool, parity_grp, host_grp, hba_wwn …) and takes a minute or more. The result: cache 278.5 GiB, microcode A3-00-00/00.

SAM-2UI returns HTTP 500 after boot
SAM4H UI unreachable / 500 shortly after a reboot
Fix

A first-boot race in aardvark-dns. Restart once the containers settle:

mgmt noderoot
systemctl restart sam4h.service
sleep 30; podman ps --format "{{.Names}} {{.Status}}"

The startup script handles this automatically (step 2): it restarts SAM4H if fewer than four containers are running.

11 Ansible & lint issues

A-1"No inventory parsed"
ansible commands report no inventory / no hosts matched
Fix

The inventory and vault paths in ansible.cfg are relative. Always run from the project root: cd /etc/ansible/Ansible_Simulator_Lab first.

A-2ansible-lint: ~360 name[unique] violations
lint gate 2 fails with hundreds of errors in vsp_direct/
Cause & fix

The vendor example playbooks carry upstream violations that aren't the lab's to fix. The .ansible-lint at the project root excludes them so the gate reflects lab-authored content only:

.ansible-lint
profile: moderate
exclude_paths:
  - playbooks/vsp_direct/
  - playbooks/ansible_vault_vars/
warn_list:
  - yaml[line-length]

With the exclude in place the gate returns to 7/7.

A-3Hitachi usage-consent notice on every play
user_consent_required appears in module output
Fix

Accept once: ansible-playbook playbooks/vsp_direct/accept_user_consent.yml. The facts-export scripts also defensively strip the user_consent_required key when locating the data payload, so the workbook is unaffected either way.

12 Facts-export issues

F-1ModuleNotFoundError: openpyxl
workbook stage aborts importing openpyxl
Cause & fix

openpyxl was installed under 3.11 but a script called bare python3 (3.9). Install under 3.11 — python3.11 -m pip install openpyxl — and confirm the scripts call python3.11. The system pip3 on Rocky 9 also lacks --break-system-packages, another sign you're on the wrong interpreter.

F-2Everything shows as added/removed, never changed
the Changes tab lists whole fact types as ADDED + REMOVED
Cause & fix

The diff key doesn't match that fact type's real identity field, so no rows line up between runs. Inspect one row's keys on the relevant All- tab and adjust KEY_FIELDS in facts_to_xlsx.py (see §05 table). Pools and host groups are the usual suspects on differing microcode.

F-3All-HBA-WWNs tab is empty
"No HBA WWNs found — all host groups empty"
Expected on a fresh simulator

The simulators set numberOfHbasPerHostGroup: 0, so there are no initiators to report — this is the correct migration baseline, not a fault. Populate host groups (Document 3) and the tab fills; the empty flags on the host-group tabs clear as counts go above zero.

F-4Share copy skipped
"/mnt/vm_share not available — skipped copy"
Fix

The VirtualBox shared folder isn't mounted. The script guards this and leaves outputs in exports/. Re-mount the share (or check the Guest Additions build — kernel headers via kernel-devel-$(uname -r)) and re-run, or copy from exports/ manually.
